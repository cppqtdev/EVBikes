01

The mental model

Qt Quick Ultralite is not Qt Quick made smaller. It is a different engine that accepts a subset of the same language.

Desktop Qt Quick parses QML, builds a scene graph and runs JavaScript, allocating as it goes. Qt for MCUs compiles your QML to C++ at build time. No parser on the device, no JavaScript engine, and — the one that bites — no heap.

Desktop Qt QuickQt for MCUsWhy
QML parsed at startupCompiled to C++ by qmltocppNo parser on device
Objects created on demandLaid out statically at build timeNo heap
Full JavaScriptA small expression subsetNo JS engine
createObject()Nothing equivalentNo heap
A Repeater growsDelegates pre-allocated from an estimateNo heap
Fonts rasterised at runtimeGlyphs rasterised at build timeNo font heap

The right-hand column is the same reason six times. There is no heap, so everything must be countable at build time. Your whole object tree is one static structure — in a backtrace it reads literally as main::item+181960.

The lie that costs the most

The desktop build delivers queued events synchronously, zero-initialises memory, resolves property reads immediately, and detects binding loops and breaks them with a warning. The device does none of those. A green desktop run means your QML parses and your logic is roughly right. Nothing about memory, timing or the renderer transfers.

Toolchain and build

Five tools in a row. When something fails, the useful question is which one — and the error text tells you, if you know the names.

The message mentionsThe toolTypical cause
could not be found in the include pathsqmltocppModule missing from MCU.qulModules

ambiguous typeqmltocppA ternary mixing an enum with an int
undefined qul_rasterBuffer_*_handlequlrcc + linkerAn image declared in two modules

Font.DemiBold undefinedqulfontcompilerA weight enum only Spark has
One module owns an image

A module must declare every image its own QML names — it does not inherit a dependency's — and no image may be declared twice. Break the first and qmltocpp fails. Break the second and it links with an undefined raster handle. If two modules want the same picture, put it in one and wrap it in a component the other uses.

ASM is not optional in project(... LANGUAGES C CXX ASM). Without it CMake silently drops the .S blobs that qulrcc and qulfontcompiler emit — no warning, and a link error pointing nowhere near the cause.

Check it yourself 
grep -rho 'assets/[^"]*\.png' qml/*/*.qmlproject | sort | uniq -d

That should print nothing. Anything it prints is a link error waiting.

03

The QML subset

Large enough to build a real HMI, small enough that you hit its edges in week one.

The JavaScript subset

There is no JavaScript engine — expressions are translated to C++, so what survives is what translates. No arrays, object literals, let/const, arrow functions or closures. Math.min and Math.max take two arguments. String.length does not exist. Function parameters and return values must be typed.

function digitAt(value: int, position: int) : string {
    var v = Math.floor(value)
    for (var i = 0; i < position; i++)
        v = Math.floor(v / 10)
    return "" + (v % 10)
}

Four traps

  • parent is a plain Item. Reading a custom property through it does not compile. Give the parent an id.
  • A property may not be called on<Something> — that spelling is a signal handler.
  • A ternary may not mix an enum with an int. Pass both through a function with a declared return type.
  • Fonts are compile-time configurations. No binding on font.pixelSize; and a font cannot be read back — someFont.pixelSize does not compile.
The one that is not a compile error

A Repeater's delegates are pre-allocated from a compile-time estimate. The model must not change while the application runs. There is no heap, so there is nowhere for a new delegate to come from — and the desktop build creates them on demand and never complains.

Repeater { model: 3
    MessageRow { visible: index < PhoneListData.contactCount } }
04

Properties and bindings

The chapter that saves the most time, because the binding engine differs from desktop Qt in a way that is invisible until it is catastrophic.

Each frame: update() → repaint() → prepareFrame() → emitChangeEvents() → DirtyList::process(). That last one is a while the list is not empty loop. If handling a dirty item puts something back on the list, the loop never drains and the frame never finishes. There is no iteration cap and no loop detector.

A Behavior on a bound property

Qt for MCUs re-runs a dirty property's binding on every read. A Behavior catches that write and restarts the animation, which dirties the property again. Anything that reads it inside another binding keeps the frame alive forever.

// hangs — bound and animated, and read by other bindings
property real shown: value
Behavior on shown { NumberAnimation { duration: 200 } }

// correct — assigned, so nothing re-runs on read
property real shown: 0
onValueChanged: shown = value
Component.onCompleted: shown = value
Behavior on shown { NumberAnimation { duration: 200 } }

In this cluster that chain was shown → shownValue → used → drawn → blanks → each digit's text, across nine readouts. The device stopped after exactly two runtime ticks, every time. The desktop build ran past tick 40, because it caches the read.

The twenty-odd other Behaviors in the same project were fine, and the difference is precise: they animate opacity, color, x, width — leaf visual properties no binding reads back.

05

The C++ bridge

This part is genuinely good. No Q_OBJECT, no moc, no qmlRegisterType, no QVariant.

struct VehicleData : public Qul::Singleton<VehicleData>
{
    enum RideMode { Eco, City, Sport };
    Qul::Property<int>      speedKmh;
    Qul::Property<bool>     absFault;
};

List the header in InterfaceFiles and qmlinterfacegenerator does the rest. No registration call anywhere.

Two that cost days

QML has one integer type. Narrow types mirrored into a desktop bridge corrupt: 8- and 32-bit survived, 16-bit did not, and every number on screen was garbage. Widen at the QML boundary.

EventQueue has a fixed capacity and drops. Eight CAN frames posted per tick into a queue of five — three lost every tick, silently, with the desktop shim delivering synchronously and hiding it completely. The queue is for crossing a boundary, not for ordinary calls.

06

Images and resources

Every image has two sizes, and they move independently.

Flash is the compressed bytes you store. Decoded is width × height × bytes_per_pixel, the space it takes once usable. Compression shrinks the first and does nothing to the second — compressed images are decompressed to be drawn. Measured on this cluster:

252images
759 KBflash
12.77 MBdecoded
17×ratio

Bytes per pixel is the main lever

FormatBytes/pxFor
Alpha81Monochrome art tinted at runtime
RGB5652Opaque colour, no alpha
RGB8883Opaque colour, full precision
ARGB88884Colour with alpha

Draw the art as a white mask and tint it with ColorizedImage: one byte a pixel, any colour. Here 247 of 252 images are Alpha8; the five that are not are photographs. And decide it by looking at the pixels — an image qualifies only if every visible pixel is pure white. Deciding from the file name is how you silently ship a 4× image.

One PNG per size

An image is drawn at its own size. A 40 px file shown at 24 px is resampled by a fraction, every frame, and the thin strokes go. Build from a vector master with the sizes in the file name.

Trim the transparent border

Lossless — not a pixel changes. Measured here:

FileCanvasActual inkEmpty
route_destination.png660×27020×13898%
hexroute_destination.png495×30512×8599%
route_straight.png660×27020×23497%

Forty files: 5.57 MB → 1.12 MB decoded.

Dead art hides inside live code

Format.routeImage() had no caller — but its eleven paths were string literals inside it, and the resource list is built from the paths the QML names. All eleven compiled in: 52 KB of flash and 1.96 MB of cache for pictures nothing drew. Ask which paths are reachable, not which appear.

Two things measurement said no to

Mirroring symmetric layers. A loose test (mean pixel difference) said 40 of 48 layers were symmetric — a 4.8 MB saving. A strict test (max difference, and count the differing pixels) said four, worth 570 KB. glow_alert had 53,530 differing pixels. The loose test was the bug.

Deleting unreferenced files. Saves nothing. Flash is built from the paths the QML names, so a file nobody references is already absent.

Desktop Qt has "memory". An MCU has three, and they behave nothing alike.

The text cache

192 KB of VRAM by default. Qul::ApplicationConfiguration lives in qul/application.h — not a header of its own — and has existed since Qt Quick Ultralite 2.1. It is passed to the constructor, not set statically.

Qul::ApplicationConfiguration config;
config.setTextCacheSize(96 * 1024);
Qul::Application app(config);
08

Layers and bits per pixel

One decision here is worth more than every other optimisation in this guide combined.

On-the-fly (OTF), the default, keeps no framebuffer — it records a command buffer and replays it through a circular line buffer. IBO is double buffered.

OTF line buffer is WIDTH × LINE_BUFFER_HEIGHT × BPP + command buffer. At 1280 wide:

Line buffer32 bpp24 bppSaved
32163,840122,88040,960
64327,680245,76081,920
128655,360491,520163,840

Qt's guidance: prefer Bpp24 for the bottom-most ItemLayer. No alpha, which an opaque bottom layer does not need, and full colour precision kept.

Don't: 16 bpp on a dark UI

RGB565 cannot hold a neutral near-black. Measured on this cluster's background: (6, 8, 9) becomes (0, 8, 8) — the whole screen picks up a green cast. In a tinted glow, distinct colours dropped from 155 to 61. Max channel error was only 7, which is why a casual look says "fine"; the defect is that it applies to every dark pixel at once and shifts the hue.

Don't: a layer per widget

Every layer brings its own buffers and command buffer, so a layer over a full-screen one can cost more than it saves. And a typical cluster has nothing to split along — here the chrome is four roughly 1120×460 layers, all overlapping. There is no rectangle that is "only the header".

09

Fonts and text

The quietest flash consumer. Each addition is invisible; the total only shows up in a map file nobody reads.

With the static engine, glyphs are rasterised at build time with FreeType. Flash holds precomputed bitmaps; nothing rasterises at runtime; and every font configuration must be resolvable at compile time.

With autoGenerateGlyphs: true the compiler includes every character appearing in a QML string literal — for every font configuration. That phrase is the whole cost model. A configuration is a distinct (family, pixelSize, weight, italic), and each gets its own glyph set.

45configurations found
124 pxlargest
~6.9 KBper glyph at 124
~69 KBten digits, one config

Nobody decided on forty-five. It accumulated one font.pixelSize: 17 at a time. Consolidate neighbours — 13/14/15 into one, 16/17/18 into one — and put the sizes in a theme, so a page that cannot name a pixel size cannot invent a forty-sixth.

Also check which faces are reachable. This project ships six Inter TTFs, but font.weight is banned by its own lint — so SemiBold and SemiBoldItalic, 944 KB, are handed to the font compiler for nothing.

Check it yourself 
grep -rn "font.weight" qml/   # nothing? only Regular/Bold × Italic are reachable
10

Profiling and debugging

Measure before you assert. This method is worth more than any individual fact in the other chapters.

The Qt desktop platform build is an ordinary native binary. Debug it like one.

gdb ./EVBikes
(gdb) run
# ...freeze... Ctrl+C
(gdb) set pagination off
(gdb) bt 60
(gdb) b Qul::Private::Application::prepareFrame
(gdb) c

Read three things off the backtrace:

  • Deep or flat? Flat and bottoming out in main means a loop that is not progressing, not runaway recursion.
  • Which loop? DirtyList::process means the list is being refilled as fast as it drains.
  • Is the frame advancing? Sample twice. If Application::update(timestamp=133) is still 133, the engine never finished that frame.

Then the breakpoint: hits immediately means frames are completing and the problem is speed; never hits means you are stuck inside one. That one bit halves the search space in thirty seconds.

Sample more than once

Two samples is a measurement; one is an anecdote. Here, two samples showed different Text objects and different Math.floor arguments — 95.2, then 105.5. That second observation was the diagnosis: the animated value was still moving while the frame was being assembled.

On a board, printf tracing earns its keep if it names the stage, not the event. The last line printed names the call that did not return. The output that cracked this project's freeze was two lines and a silence:

[tick 2] after periodic
[tick 2] done
            ← nothing, ever again

Safety and certification

The difference between a demo and a product, if you build clusters, medical displays or industrial panels.

Qt Safe Renderer is a separate component running alongside Qt Quick Ultralite. It renders the safety-critical items and verifies the output rather than trusting the main UI stack.

StandardLevel
ISO 26262:2018-6ASIL D
ISO 26262:2018-8 §11ASIL D
IEC 61508:2010-3SIL 3
EN 50128:2011 6.7.4SIL 4 (railway)
IEC 62304:2015Class C (medical)
Read the scope line

The certification covers the content inside the SafeRenderer namespace — the certified runtime. Your application is not certified because you linked it. Your telltales are rendered and verified by a certified component; your own code and system design are still yours to argue for.

SafeImage, SafePicture and SafeText look like their ordinary counterparts. Constraints that shape the layout: the root needs fixed dimensions, safe items do not support rotation, and an invisible safe item still appears as a visible rectangle — a deliberate fail-safe.

What it does not cover

Qt Safe Renderer makes sure the lamp you drew is the lamp that reached the glass. It has nothing to say about whether you drew the right lamp. For a road vehicle that is UNECE Regulation No. 121 (free PDF, official symbol drawings in the annex) and ISO 2575.

Easy to get wrong, invisible when you do

In this cluster the engine-malfunction lamp was drawn as an oil can — which is the oil pressure symbol — and the brake warning was a power symbol in brackets instead of the specified exclamation. Both had been in the design for months. Each looked plausible alone.

The habit

A cheap measurement beats an expensive argument, almost always — and the measurement has to be the right one. A mirror-symmetry test using mean pixel difference promised 4.8 MB; the max difference said 570 KB. One of those numbers would have shipped visible damage.
