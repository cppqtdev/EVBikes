# 07 · Build, run and flash

## 1. Install (one time)

- **Qt Online Installer** → select:
  - Qt Creator (latest)
  - **Qt for MCUs 2.12.x** (LTS) → *Desktop* platform + your board (e.g. NXP MIMXRT1170-EVKB, Infineon TRAVEO T2G)
  - Qt Design Studio (optional, for UI work)
- Board tools (install what the Qt for MCUs "Getting started" page for your board lists):
  - NXP: MCUXpresso SDK + MCUXpresso IDE / LinkServer, ARM GCC or IAR
  - Infineon: ModusToolbox / Infineon Auto Flash Utility, GHS or IAR
  - STM: STM32CubeProgrammer, ARM GCC
- CMake ≥ 3.21 and Ninja.
- Qt Creator → *Preferences → Devices → MCU*: pick Qt for MCUs SDK path, the target, and let it create a **kit**.

> A licence for Qt for MCUs is needed (evaluation licence is available from Qt).

## 2. Open the project

- Qt Creator → *Open Project* → `EVBikes/CMakeLists.txt`.
- Pick the **Qt for MCUs – Desktop** kit first.
- The old Qt 6 desktop template files were moved to `legacy/qt6-desktop-template/` (not built).

## 2b. Run with a normal Qt 6 kit (no Qt for MCUs licence needed)

If CMake cannot find the Qt for MCUs SDK (`Qul`), it builds a **plain Qt 6 desktop app** from the same QML and C++ backend (folder `desktop/`).

- Kit: any Qt **6.5 or newer** desktop kit (e.g. *Qt 6.8.x for macOS*).
- Qt Creator: *Build → Clear CMake Configuration*, then *Build → Run CMake*, then **Run**.
- CLI:

```bash
cmake -S . -B build/qt6 -G Ninja -DCMAKE_PREFIX_PATH=$HOME/Qt/6.8.x/macos
cmake --build build/qt6
open build/qt6/desktop/EVBikes.app        # macOS
```

How it works:

| MCU piece | Qt 6 desktop replacement |
|---|---|
| `Qul::Property`, `Qul::Singleton`, `Qul::Signal`, `Qul::EventQueue` | `desktop/qul_shim/qul/*.h` (same API + change hooks) |
| C++ singletons exposed to QML by `qmlinterfacegenerator` | `desktop/bridge/QulQmlBridge.*` generated by `python3 tools/generate_desktop_bridge.py` |
| `QtQuickUltralite.Extras` → `ColorizedImage` | `desktop/extras/ColorizedImage.*` (QQuickPaintedItem) |
| `.qmlproject` modules | `qt_add_qml_module` in `qml/*/CMakeLists.txt` |
| `ImageFiles` / `FontFiles` | `qt_add_resources` (same `qrc:/assets/...` paths) |

Rules so both builds keep working:

- After changing any header in `qml/backend/`, run `python3 tools/generate_desktop_bridge.py`.
- A new QML file must be added to **both** the module `.qmlproject` and the module `CMakeLists.txt`.
- The Qt 6 build accepts more QML than Ultralite does. Always run `python3 tools/qul_lint.py qml` too.
- `Connections` handlers use `function onFoo(arg: type) { ... }` (works in both builds).
- `Keys.onPressed` keeps the injected `event` form from the Qt for MCUs docs; the desktop build hides that one deprecation warning (`qt.qml.context`) in `desktop/main.cpp`.

## 3. Run on desktop with Qt for MCUs (simulator)

```bash
# command line alternative
cmake -S . -B build/desktop -G Ninja \
  -DQul_ROOT=$HOME/Qt/QtMCUs/2.12.2 \
  -DQUL_PLATFORM=Qt \
  -DCMAKE_TOOLCHAIN_FILE=$HOME/Qt/QtMCUs/2.12.2/lib/cmake/Qul/toolchain/<host-toolchain>.cmake
cmake --build build/desktop
./build/desktop/EVBikes
```

- Demo PIN: **1234** (Up/Down change digit, Enter next digit).
- Keys: ← → pages, Enter OK, Esc back, **M next scenario** (City Eco → Sport → Low tyre → Overheat → Crash).
- Exact toolchain file names differ per version — Qt Creator fills them in for you; copy them from *Projects → Build → CMake* if you want CLI builds.

## 4. Host unit tests (no Qt needed)

```bash
cmake -S . -B build/tests -DEVB_BUILD_HOST_TESTS=ON
cmake --build build/tests
ctest --test-dir build/tests --output-on-failure
python3 tools/qul_lint.py qml
```

- `core_tests`: CAN decoding, timeouts, phone frames (noise, CRC error, split packets), alerts, utilities.
- `backend_smoke`: runs the full simulator → decoder → singletons → alerts path with mock Qul headers.

## 5. Build for the board

- Select the board kit (e.g. *Qt for MCUs 2.12 – MIMXRT1170-EVKB-FREERTOS*).
- CMake picks:
  - `src/os/main_freertos.cpp` when `QUL_OS=FreeRTOS`
  - `src/platform/board/PlatformBoard.cpp` for any non-desktop platform
- Fill the **TODOs in `PlatformBoard.cpp`**: CAN init + RX ISR, UART to BLE module, GPIO buttons, backlight PWM.
- For RT1170-EVKB (720×1280 portrait panel): either set `displayRotationAngle: 90` in `MCU.Config` and design at 1280×720, or change `Theme.screenWidth/Height` and layout.

## 6. Flash

- Qt Creator: connect the board USB debug port → **Run** (it builds and flashes with the kit's flash tool).
- CLI: `cmake --build build/rt1170 --target flash_EVBikes` (target name comes from the Qt for MCUs CMake helpers; check `cmake --build build/rt1170 --target help`).
- Big assets (images, fonts) are placed in external QSPI/NOR flash by the platform linker script. Keep an eye on the map file.

## 7. Bench test with a real CAN bus

- USB-CAN adapter (PCAN-USB, CANable, Kvaser) + `tools/dbc/evbike.dbc` in SavvyCAN / BusMaster to send VCU/BMS frames.
- `python3 tools/phone_link_sim.py /dev/tty.usbserial-XXXX` over a USB-UART adapter to the BLE module UART pins → simulates the phone.
- Turn off demo mode on the board: Settings → Demo mode → Off (or set `demoMode`/`Simulator.running` default to false in C++ for production).

## 8. Release checklist

- `Simulator.running` default **false** in production builds.
- Change the default PIN handling (`SystemData.cpp`) to a PIN stored in secure storage / set from the app.
- Enable resource checksum verification and watchdog.
- Run `QulPerfOverlay` (Profiling module) once on the board to check FPS (frames per second) and memory.
